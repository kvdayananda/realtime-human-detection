# FitRange Mirror: Independent Human Annotation Guidelines

**Version:** 1.0  
**Target:** Independent Human Ground-Truth Benchmark for FitRange Mirror  
**Directory:** `dataset/independent_validation/`  

---

## 1. Objective and Core Principles

This document provides definitive instructions for manual, human-verified annotation of images in `dataset/independent_validation/`.

### The Cardinal Rule:
> [!IMPORTANT]
> **Zero Model Predictions in Ground Truth:**
> Annotations must be produced or verified by a human annotator using manual annotation tooling (such as Labelme or CVAT).
> **Never** copy bounding boxes or masks generated by `HumanDetectorONNX`, `HumanSegmenterONNX`, or any automated model into ground-truth files. Automated pseudo-labels invalidate empirical benchmark evaluation.

## 3. Detection Annotation Specification

### Format: Standard YOLO Normalized Format
Each detection file is a plain text file (`.txt`) with one line per visible person:
```
<class_id> <x_center> <y_center> <width> <height>
```

* **`class_id`:** Always integer `0` (Person). No other class IDs are permitted.
* **`x_center`:** Horizontal midpoint of the box normalized by image width: $[0.0, 1.0]$.
* **`y_center`:** Vertical midpoint of the box normalized by image height: $[0.0, 1.0]$.
* **`width`:** Bounding box width normalized by image width: $(0.0, 1.0]$.
* **`height`:** Bounding box height normalized by image height: $(0.0, 1.0]$.

### Bounding Box Annotation Rules:
1. **Tight Boundary:** The box must tightly enclose all visible parts of the person (head, hair, limbs, shoes, and clothing).
2. **Partial Visibility & Frame Edges:** If a person extends beyond the image border, clip the box at the visible frame edge. Do not extrapolate outside the frame boundaries.
3. **Multiple Persons:** If multiple people appear in a single image (e.g. background trainers or gym members), annotate **each person** as a separate line in the `.txt` file.
4. **Side-Facing / Profiles:** Draw the box to enclose the complete silhouette, including outstretched arms or rear heels.
5. **Loose Clothing & Gear:** Enclose hoodies, jackets, loose sweatpants, and gym bags currently worn on the body. Do not enclose detached gym equipment (dumbbells, barbells) unless held within the body silhouette.
6. **Occlusion Handling:** If a person is partially occluded by gym machinery or furniture:
   * If $> 20\%$ of the body or head/torso is visible, draw a box enclosing the visible parts of that person.
   * If heavily occluded ($< 15\%$ visible, e.g. only a foot behind a bench), omit the box.
7. **Negative Images:** For all images named `val_neg_XXX.png`, the corresponding `annotations/detection/val_neg_XXX.txt` file must be **completely empty (0 bytes)**.

## 4. Segmentation Annotation Specification

### Format: Single-Channel 8-Bit Grayscale PNG (`uint8`)
Each segmentation mask is a PNG image matching the exact pixel dimensions `(height, width)` of the corresponding image in `images/`:

* **`0` (Black):** Background pixels.
* **`255` (White):** Human foreground pixels.
* **No intermediate values:** Values other than `0` and `255` are strictly rejected.

### Mask Annotation Rules:
1. **Anatomical Precision:** Include head, skin, hair, torso, arms, hands, legs, and feet.
2. **Clothing Coverage:** Include all clothing, shoes, hats, and fitness wearables.
3. **Negative Spaces (Holes):** Ensure spaces between arms and torso, or between legs, are labeled as background (`0`). Do not fill in background gaps.
4. **Carried / Held Equipment:** Do not include handheld barbells, dumbbells, water bottles, or phones in the person mask unless they directly obscure body pixels.
5. **Multiple Persons:** All people in the frame are marked with pixel value `255` (binary human presence).
6. **Negative Images:** For all images named `val_neg_XXX.png`, the mask in `annotations/segmentation/val_neg_XXX.png` must be an **all-black image (all pixels = 0)**.

## 5. Recommended Annotation Tooling

### Option A: Labelme (Recommended for Polygon & Box Annotation)
1. Install Labelme (in your annotation environment, e.g. `C:\vf-label\venv`):
   ```bash
   pip install labelme
   ```
2. Launch Labelme **strictly for positive images** (avoids negative control images):
   * On Windows PowerShell:
     ```powershell
     labelme (Get-ChildItem dataset/independent_validation/images/val_pos_*.png) --nodata
     ```
   * Or open specific batches:
     ```powershell
     labelme dataset/independent_validation/images/val_pos_001.png --nodata
     ```
   > [!WARNING]
   > Do not open the entire `dataset/independent_validation/images/` directory without filtering, because `val_neg_001.png` - `val_neg_030.png` will appear first alphabetically. The 30 negative control images must remain empty.

3. Annotation Procedure:
   * Draw polygons or tight bounding boxes around each human subject with label `person`.
   * Save the `.json` files alongside the images.
4. Convert Labelme JSON to YOLO boxes and binary PNG masks:
   ```bash
   python -m ai.evaluation.convert_labelme_to_ground_truth \
       --json-dir dataset/independent_validation/images \
       --out-det dataset/independent_validation/annotations/detection \
       --out-seg dataset/independent_validation/annotations/segmentation
   ```

### Option B: CVAT (Computer Vision Annotation Tool)
1. Create a task in CVAT with label `person`.
2. Upload the images from `dataset/independent_validation/images/`.
3. Annotate bounding boxes (for detection) and polygons (for segmentation).
4. Export task:
   * For Detection: Export as **YOLO 1.1**.
   * For Segmentation: Export as **Segmentation Mask 1.1**.
5. Place the exported `.txt` files in `annotations/detection/` and mask `.png` files in `annotations/segmentation/`.

## 6. Automated Quality Assurance & Validation

Before any evaluation script is executed, run the automated validator:
```bash
python dataset/independent_validation/validate_annotations.py
```

The validation script enforces:
* [x] Every image has both a detection `.txt` file and a segmentation `.png` file.
* [x] Negative images have empty detection files and all-zero masks.
* [x] Positive images have non-empty detection files and non-zero masks.
* [x] All YOLO coordinates are within $[0.0, 1.0]$ with valid widths and heights.
* [x] All masks match the exact width and height of the source image.
* [x] All mask pixel values are strictly `{0, 255}`.
* [x] Manifest matches file inventory and reflects correct annotation status.
